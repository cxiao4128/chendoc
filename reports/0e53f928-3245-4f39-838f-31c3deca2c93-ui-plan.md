## 一、背景与目标

ChenDoc v2.8.0 已具备完整的文档管理、收集表、分享审核链，但存在三类 UI 断链：
1. **可靠性断链**：会话续期、收集表真实可用性有功能缺陷，用户实际无法正常使用。
2. **信息密度断链**：文档工作台信息过载，状态和操作含义不清晰。
3. **视觉一致性断链**：收集表引入第三方色彩 token，与陈书淡紫/克制蓝体系冲突。

本计划确定具体修改文件、优先级、时间表、测试验收标准，确保向后兼容和渐进增强。

## 三、具体修改方案

### P0-1：会话续期修复

**文件**：
- `apps/admin/src/api/request.ts`
- `server/src/modules/auth/session.service.ts`

**修改内容**：
1. `request.ts` 第 118 行：`buildAuthorization()` 是异步，必须 `await` 后再发 `/api/auth/refresh` 请求
2. `session.service.ts` 续期后更新 token 摘要，串行处理旧 token 宽限窗口
3. 增加前端 SessionStatusBanner（已有 `SessionStatusBanner.vue`），续期失败时主动提示而非静默跳转

**向后兼容**：仅修逻辑，不改变 API 签名和 Gateway 封装方式。

**验收标准**：
- [ ] 90 分钟持续编辑后会话不中断
- [ ] 刷新页面后内容恢复
- [ ] 并发请求不会导致多个 refresh 并发发出
- [ ] 会话即将过期时页面顶部显示 Banner

---

### P0-2：收集表真实可用性

**文件**：
- `server/src/modules/forms/forms.public.ts`
- `server/src/app.ts`（CSP 配置）
- `server/src/modules/forms/forms.service.ts`
- `server/src/modules/forms/forms.public.routes.ts`

**修改内容**：
1. 表单公开页设置与 nonce 匹配的 CSP：`script-src 'self' 'nonce-{nonce}'`，移除全局 `script-src 'self'`
2. 修正 `maxSubmissions` 数值写入类型（`number` 而非布尔），提交时正确判断上限
3. 修正"允许重复提交"在提交入口的执行判断
4. 公开页第三次提交时前端传递 `captchaId`/`captchaCode`，接入现有验证码组件
5. 提交失败后保留已填内容，不清空表单

**临时措施**：功能修复前，在收集表编辑器增加"实验功能"标记横幅。

**向后兼容**：不影响已发布的表单结构；nonce CSP 向后兼容无内联脚本的页面。

**验收标准**：
- [ ] 浏览器控制台无 CSP 违规，提交脚本正常执行
- [ ] `maxSubmissions=5` 时第 6 次提交返回明确拒绝
- [ ] 不允许重复时同一来源第二次提交返回明确拒绝
- [ ] 第三次提交正确触发验证码流程
- [ ] 验证码错误后表单内容保留

### P1-1 & P1-2：文档工作台信息密度

**文件**：`apps/admin/src/pages/docs/DocListPage.vue`

**修改内容**：
1. 默认列表列：文档、状态、更新时间、分享、操作。**所有者列**默认隐藏（Pinia store 控制，多用户模式时可开启）
2. "上传文档"与"导入文档"拆分为两个明确不同的操作按钮；上传=附件文件，导入=解析正文
3. 右侧"存储概览、最近动态"栏可折叠，状态保存到 localStorage
4. "最近动态"改为可点击事件列表（如：谁在何时打开了某文档），不重复文档树内容

**组件抽象建议**：
- `DocListColumns.vue`：列配置管理，可复用
- `RecentActivity.vue`：独立动态组件，支持折叠

**向后兼容**：列配置默认值向后兼容；已有文档不受影响。

**验收标准**：
- [ ] 单用户默认不显示"所有者"列
- [ ] 上传/导入按钮文案明确区分
- [ ] 右侧栏折叠后文档列表宽度自动扩展
- [ ] 刷新后折叠状态保持

### P1-3：分享状态统一

**文件**：
- `apps/admin/src/components/docs/ShareDialog.vue`
- `server/src/modules/shares/shares.service.ts`

**修改内容**：
1. 统一为状态链：**草稿 → 已发布 → 待审核 → 已公开/已拒绝/已关闭**
2. 分享面板显示：谁能访问、是否需要密码、何时失效（已有数据，需展示文案）
3. 分享审核拒绝后提供单一"修改并重新提交"按钮
4. 状态文案替换：避免"已分享"与"已发布"混用

**向后兼容**：服务端返回字段不变；前端展示文案调整，不改变 API 行为。

**验收标准**：
- [ ] 状态文案在面板内一致，不出现"已发布/已分享/审核中"三态并存
- [ ] 面板展示当前分享的完整访问条件摘要
- [ ] 拒绝后重新提交入口唯一且明确

### P1-4：收集表视觉一致性

**文件**：`apps/admin/src/pages/forms/css/form-editor.css`

**修改内容**：
1. 删除腾讯文档风格的绿色/蓝色局部变量
2. 改用陈书全局 `--cd-*` token：
   - `--cd-primary` / `--cd-primary-hover`
   - `--cd-bg` / `--cd-surface`
   - `--cd-text` / `--cd-text-muted`
   - `--cd-border`
3. 保留表单布局本身（题型面板、字段配置、预览三区），只替换色彩变量引用
4. 表单特有变量（如题型标签色）定义为 `--cd-form-*`，收敛在表单组件内

**组件抽象**：
- 表单组件统一使用全局 token，不在组件内声明色彩
- 可提取 `apps/admin/src/pages/forms/css/form-tokens.css` 作为表单层 token 覆盖

**向后兼容**：token 覆盖不改变 DOM 结构；配色变化对外接口无影响。

**验收标准**：
- [ ] 表单编辑页主色调与陈书淡紫/克制蓝体系一致
- [ ] 不出现绿色/蓝色魔法数字
- [ ] 响应式布局不变（桌面三栏、移动堆叠）

---

### P1-5：WCAG AA 对比度

**文件**：全局 CSS token 文件

**修改内容**：
1. 扫描所有 `.vue` 文件中的硬编码淡紫色文字，替换为全局 token
2. 全局 token 中调高文字与背景对比度：淡紫文字 `rgba(120,100,180,0.8)` → 至少 `#555` 或更深
3. 图标按钮增加可见 `:focus-visible` 轮廓（`outline: 2px solid var(--cd-primary)`）
4. 运行 `axe-core` 或 Lighthouse Accessibility 审计，达标 WCAG AA

**向后兼容**：仅改变色彩值，DOM 结构不变。

**验收标准**：
- [ ] Lighthouse Accessibility ≥ 90
- [ ] 无前景/背景对比度 < 4.5:1 的文本
- [ ] 键盘导航时焦点可见
