## 一、文档概述

### 1.1 目的

本 PRD 定义 ChenDoc 全量重构的功能需求，为架构设计、技术实现和质量验收提供完整的产品规范。

### 1.2 项目背景

ChenDoc v2.9.3 是轻量个人文档管理、知识发布和数据收集系统。当前存在以下核心问题：

| 问题类型 | 具体问题 | 影响 |
|----------|----------|------|
| 视觉一致性 | doc-list.css 等文件大量硬编码颜色，暗色模式失效 | 用户体验割裂 |
| 无障碍 | ARIA 标签缺失，键盘导航不完整 | WCAG AA 不达标 |
| 移动端体验 | 编辑器、收集表在移动端交互成本高 | 移动用户流失 |
| 功能缺失 | 无标签系统、看板视图、导出、评论等 | 竞争力不足 |
| 性能问题 | 大文档（>1MB）编辑卡顿，搜索体验差 | 用户体验差 |

### 1.3 产品定位（不变）

- **核心用户**：个人站长、小型私有发布流程
- **产品边界**：个人文档管理、知识发布、数据收集
- **不做**：企业 OA、团队协作、CRM、营销页、AI 仪表盘

## 二、深色模式需求

### 2.1 用户故事

> **作为**经常在夜间工作的用户，**我想要**系统支持深色模式，**以便**减少眼睛疲劳并适应低光环境。

### 2.2 功能描述

构建完整的深色模式系统，支持：
1. **系统级跟随**：自动跟随操作系统偏好
2. **手动切换**：用户可在设置中手动选择浅色/深色/跟随系统
3. **持久化**：主题选择保存到用户偏好设置
4. **平滑过渡**：主题切换时有平滑动画过渡

### 2.3 交互设计要点

| 场景 | 行为 |
|------|------|
| 首次使用 | 检测系统偏好并应用 |
| 手动切换 | 立即应用，保存到服务端用户偏好 |
| 主题切换动画 | 150ms ease-out 过渡，不闪烁 |
| 减少动画偏好 | `prefers-reduced-motion` 时禁用过渡动画 |

### 2.4 技术要点

**CSS 变量设计**：
```css
/* 浅色模式（默认） */
:root {
  --cd-bg: #ffffff;
  --cd-surface: #f5f6f8;
  --cd-text: #1a1a2e;
  --cd-text-muted: #666666;
  --cd-border: #e8eaed;
  --cd-shadow: rgba(0, 0, 0, 0.06);
}

/* 深色模式 */
[data-theme="dark"] {
  --cd-bg: #0a0a0a;
  --cd-surface: #1a1a1a;
  --cd-text: #e8e8e8;
  --cd-text-muted: #888888;
  --cd-border: #2a2a2a;
  --cd-shadow: rgba(0, 0, 0, 0.3);
}
```

**需要迁移的硬编码颜色**（来自 ui-analysis-report.md）：
- doc-list.css 行 12, 18, 84, 166, 173, 256, 268, 276 的 `#fff` → `var(--cd-bg)`
- 行 46, 100, 116, 229, 645, 695, 696, 713, 757 的 `#f5f6f8`, `#f0f2f5`, `#e8eaed` → `var(--cd-surface)`
- 行 455 的 `rgba(37, 99, 235, 0.28)` → `var(--cd-accent-soft)`
- 行 604 的 `rgba(5, 150, 105, 0.18)` → `var(--cd-brand-accent-soft)`

### 2.5 优先级

**P0**（必须）

### 2.6 验收标准

- [ ] 浅色/深色模式切换无闪烁
- [ ] 深色模式下所有页面元素颜色正确
- [ ] 主题偏好持久化（刷新后保持）
- [ ] 跟随系统偏好正常工作
- [ ] `prefers-reduced-motion` 用户无动画
- [ ] 无 WCAG AA 对比度不达标文本

## 三、移动端编辑器优化需求

### 3.1 用户故事

> **作为**经常在移动设备上记录灵感的我，**我想要**编辑器在手机上也能高效使用，**以便**不错过任何创作时刻。

### 3.2 功能描述

1. **触控优化**：
   - 工具栏按钮触控区域 ≥ 44px
   - 长按文本弹出上下文菜单（代替右键）
   - 双击文本进入选择模式

2. **移动端布局**：
   - 工具栏精简为：加粗、斜体、列表、缩进、图片
   - 其他格式化通过"更多"菜单访问
   - 底部固定保存按钮

3. **手势支持**：
   - 左滑文档返回列表
   - 右滑呼出工具栏
   - 下拉刷新文档列表

4. **键盘适配**：
   - 自动弹出虚拟键盘时布局自动调整
   - 工具栏不被键盘遮挡

### 3.3 交互设计要点

| 场景 | 行为 |
|------|------|
| 首次进入移动编辑器 | 显示手势提示浮层（可关闭） |
| 工具栏按钮点击 | 视觉反馈（缩放 0.95 + 颜色变化） |
| 键盘弹出 | 工具栏自动收起到只显示核心按钮 |
| 文档保存 | 显示简洁的保存状态指示器 |

### 3.4 优先级

**P0**

### 3.5 验收标准

- [ ] 390px 宽度下可完成完整编辑流程
- [ ] 触控按钮 ≥ 44px
- [ ] 键盘弹出时内容不被遮挡
- [ ] 编辑器加载时间 < 2s（3G 网络）
- [ ] 手势操作有视觉/触觉反馈

## 四、增强标签系统需求

### 4.1 用户故事

> **作为**有大量文档的用户，**我想要**支持多级标签和颜色标签，**以便**更高效地组织和检索文档。

### 4.2 功能描述

#### 4.2.1 多级标签

1. **层级结构**：支持最多 3 级标签嵌套
   - 示例：`工作/项目A/需求文档`
2. **标签管理**：
   - 创建/编辑/删除标签
   - 重命名标签自动更新所有文档
   - 删除标签时可选替换或移除

#### 4.2.2 颜色标签

1. **预设颜色**：8 种预设颜色（红、橙、黄、绿、青、蓝、紫、灰）
2. **自定义颜色**：支持 HEX 颜色选择器
3. **标签样式**：标签左侧显示颜色条（4px 宽）

#### 4.2.3 标签应用

1. 每个文档支持多个标签
2. 文档列表支持按标签筛选（支持多选）
3. 标签云视图：显示所有标签及文档数量

### 4.3 交互设计要点

| 场景 | 行为 |
|------|------|
| 创建标签 | 弹出模态框，输入名称、选择颜色、选择父级 |
| 应用标签 | 点击文档标签区域 → 标签选择下拉 |
| 筛选标签 | 标签筛选器支持 AND/OR 逻辑 |
| 标签冲突 | 删除父标签时提示如何处理子标签 |

### 4.4 数据库设计要点

```
tags:
  - id: 主键
  - name: 字符串（必填，唯一）
  - color: 字符串（HEX，nullable）
  - parent_id: 外键（nullable，指向自身）
  - created_at: 时间戳

doc_tags:
  - doc_id: 外键
  - tag_id: 外键
  - PRIMARY KEY (doc_id, tag_id)
```

### 4.5 优先级

**P1**

### 4.6 验收标准

- [ ] 可创建/编辑/删除标签
- [ ] 可创建最多 3 级嵌套标签
- [ ] 标签支持 8 种预设颜色 + 自定义 HEX
- [ ] 单个文档可添加多个标签
- [ ] 文档列表支持按标签筛选
- [ ] 标签云显示文档数量
- [ ] 删除父标签时子标签处理正确

## 五、看板视图需求

   - 默认泳道：草稿、待审核、已发布

2. **拖拽操作**：

   - 拖拽时显示放置预览

4. **泳道管理**：
   - 添加/删除/重命名泳道
   - 泳道顺序可调整
   - 泳道颜色区分

### 5.3 交互设计要点

| 场景 | 行为 |
|------|------|
| 进入看板视图 | 横向滚动，泳道等宽 |
| 拖拽文档 | 原位置显示占位符，拖拽时文档阴影加深 |
| 拖拽到泳道 | 释放后文档落入泳道顶部，触发保存 |

## 六、PDF/Word 导出功能需求

### 6.1 用户故事

> **作为**需要与他人分享文档的用户，**我想要**导出为 PDF 和 Word 格式，**以便**在不使用 ChenDoc 的情况下查看和编辑文档。

### 6.2 功能描述

#### 6.2.1 PDF 导出

1. **样式保持**：
   - 保持文档排版样式
   - 支持页眉页脚（可选）
   - 支持页码
   - 支持标题自动分页

2. **导出选项**：
   - 单文档 / 整个文档夹
   - 是否包含评论
   - 纸张大小（A4 / Letter）
   - 方向（纵向 / 横向）

#### 6.2.2 Word 导出

1. **格式兼容**：
   - 输出 .docx 格式
   - 保留基本格式（标题层级、粗体、斜体、列表）
   - 图片转为嵌入格式

2. **导出选项**：
   - 是否包含评论
   - 是否保留 ChenDoc 特定标记

### 6.3 技术实现建议

| 方案 | 优点 | 缺点 |
|------|------|------|
| 后端 Puppeteer/Playwright 渲染 | 样式精确，浏览器兼容 | 服务器资源消耗大 |
| 前端 jsPDF + docx.js | 无服务器压力 | 样式兼容性问题 |
| 混合方案（简单文档前端，复杂后端） | 平衡性能和兼容性 | 实现复杂度高 |

**推荐**：混合方案，使用前端库处理简单文档，后端处理复杂排版。

### 6.4 优先级

**P2**

### 6.5 验收标准

- [ ] 单文档可导出 PDF
- [ ] 单文档可导出 Word (.docx)
- [ ] PDF 样式与编辑器显示一致
- [ ] Word 可在 Microsoft Word / WPS 中打开
- [ ] 导出过程显示进度条
- [ ] 导出失败有明确错误提示
- [ ] 移动端可发起导出（下载到设备）

## 七、文档评论/批注功能需求

### 7.1 用户故事

> **作为**需要审阅他人文档的用户，**我想要**在文档中添加评论和批注，**以便**提供反馈和讨论。

### 7.2 功能描述

#### 7.2.1 行内批注

1. **选中文本批注**：
   - 选中文字后点击批注按钮
   - 批注标记显示在文字右侧（竖线标记）
   - 悬停显示批注内容预览

2. **批注线程**：
   - 每条批注可回复（形成线程）
   - 批注可标记为已解决
   - 已解决批注可折叠显示

#### 7.2.2 文档评论

1. **整体评论**：
   - 文档末尾显示评论列表
   - 支持 @提及
   - 评论按时间排序

2. **评论通知**：
   - 新评论通过站内信通知
   - 可配置邮件通知

#### 7.2.3 批注颜色

每个用户的批注使用唯一颜色，便于区分。

### 7.3 交互设计要点

| 场景 | 行为 |
|------|------|
| 选中文本点击批注 | 弹出批注输入框，光标定位 |
| 悬停批注标记 | 显示批注内容气泡 |
| 点击批注标记 | 滚动到批注位置，高亮显示 |
| 回复批注 | 内联回复输入框 |
| 解决批注 | 批注变灰，点击可重新打开 |

### 7.4 数据库设计要点

```
comments:
  - id: 主键
  - doc_id: 外键
  - user_id: 外键
  - parent_id: 外键（nullable，支持回复）
  - content: 文本（富文本）
  - start_offset: 整数（nullable，行内批注起点）
  - end_offset: 整数（nullable，行内批注终点）
  - is_resolved: 布尔（默认 false）
  - created_at: 时间戳
  - updated_at: 时间戳

doc_meta:
  - doc_id: 主键
  - comment_count: 整数
  - unresolved_count: 整数
```

### 7.5 优先级

**P1**

### 7.6 验收标准

- [ ] 可选中文字添加行内批注
- [ ] 批注在文档中显示标记
- [ ] 批注支持回复形成线程
- [ ] 批注可标记为已解决
- [ ] 文档整体评论功能
- [ ] 评论/批注在导出 PDF 中包含
- [ ] 移动端可查看和添加批注

## 八、定时发布/草稿自动过期需求

### 8.1 用户故事

> **作为**需要在特定时间发布内容的用户，**我想要**设置定时发布，**以便**预先安排内容发布时间。

> **作为**希望保持文档库整洁的用户，**我想要**草稿自动过期，**以便**自动清理长期未完成的文档。

### 8.2 功能描述

#### 8.2.1 定时发布

1. **发布计划**：
   - 设置具体发布时间（日期 + 时间）
   - 支持时区设置
   - 可取消或修改已计划发布

2. **状态显示**：
   - 已计划文档显示"定时发布"标签
   - 显示计划发布时间
   - 倒计时显示（距发布剩余时间）

3. **技术实现**：
   - 后端定时任务检查待发布文档
   - 或使用消息队列延迟处理

#### 8.2.2 草稿自动过期

1. **过期策略**：
   - 可设置全局默认过期时间（如：30 天未编辑自动转为草稿过期）
   - 也可为单个文档设置过期时间
   - 过期后文档移至回收站（保留 7 天后可永久删除）

2. **通知提醒**：
   - 过期前 3 天发送站内通知
   - 过期当天发送邮件通知（可选）

3. **过期处理**：
   - 自动移入回收站
   - 标记"已过期"状态
   - 可手动恢复

### 8.3 交互设计要点

| 场景 | 行为 |
|------|------|
| 设置定时发布 | 日期时间选择器 + 时区下拉 |
| 计划文档列表 | 独立标签页，显示所有计划文档 |
| 草稿过期警告 | 文档卡片显示过期倒计时 |
| 过期文档处理 | 显示过期原因和恢复按钮 |

### 8.4 优先级

**P2**

### 8.5 验收标准

- [ ] 可设置文档定时发布时间
- [ ] 定时文档在计划时间自动发布
- [ ] 可取消或修改计划
- [ ] 可设置草稿过期时间
- [ ] 过期文档自动移入回收站
- [ ] 过期前有通知提醒
- [ ] 过期文档可手动恢复

## 九、开放 API 设计需求

### 9.1 用户故事

> **作为**需要将 ChenDoc 集成到其他系统的开发者，**我想要**完整的 REST API，**以便**自动化工作流程和二次开发。

### 9.2 功能描述

#### 9.2.1 API 范围

| 模块 | 接口 | 说明 |
|------|------|------|
| 认证 | `POST /api/v1/auth/token` | 获取访问令牌 |
| | `POST /api/v1/auth/refresh` | 刷新令牌 |
| 文档 | `GET /api/v1/docs` | 列表 |
| | `POST /api/v1/docs` | 创建 |
| | `GET /api/v1/docs/:id` | 详情 |
| | `PUT /api/v1/docs/:id` | 更新 |
| | `DELETE /api/v1/docs/:id` | 删除 |
| 标签 | `GET /api/v1/tags` | 列表 |
| | `POST /api/v1/tags` | 创建 |
| | `PUT /api/v1/tags/:id` | 更新 |
| | `DELETE /api/v1/tags/:id` | 删除 |
| 分享 | `GET /api/v1/shares` | 列表 |
| | `POST /api/v1/shares` | 创建 |
| | `PUT /api/v1/shares/:id` | 更新 |
| | `DELETE /api/v1/shares/:id` | 删除 |
| 收集表 | `GET /api/v1/forms` | 列表 |
| | `POST /api/v1/forms` | 创建 |
| | `GET /api/v1/forms/:id` | 详情 |
| | `GET /api/v1/forms/:id/submissions` | 提交列表 |
| 搜索 | `POST /api/v1/search` | 全文搜索 |

#### 9.2.2 API 设计规范

1. **认证方式**：
   - Bearer Token（JWT）
   - API Key（可选，用于服务间调用）

2. **版本控制**：
   - 路径版本：`/api/v1/*`
   - 长期维护旧版本 1 年

3. **响应格式**：
   ```json
   {
     "success": true,
     "data": { ... },
     "meta": {
       "page": 1,
       "pageSize": 20,
       "total": 100
     }
   }
   ```

4. **错误格式**：
   ```json
   {
     "success": false,
     "error": {
       "code": "DOC_NOT_FOUND",
       "message": "文档不存在"
     }
   }
   ```

5. **限流**：
   - 未认证：60 次/分钟
   - 已认证：300 次/分钟
   - 返回 `X-RateLimit-*` 响应头

#### 9.2.3 API 文档

- 使用 OpenAPI 3.0 规范
- 提供交互式 Swagger UI
- 提供 API Key 管理界面

### 9.3 优先级

**P2**

### 9.4 验收标准

- [ ] 完整的 REST API 覆盖核心功能
- [ ] API 响应格式统一
- [ ] 错误处理规范
- [ ] 限流机制正常工作
- [ ] OpenAPI 文档完整
- [ ] Swagger UI 可访问
- [ ] API Key 可在设置中管理

## 十、全文搜索优化需求

### 10.1 用户故事

> **作为**有大量文档的用户，**我想要**快速准确的全文搜索，**以便**快速找到所需内容。

### 10.2 功能描述

#### 10.2.1 搜索能力

1. **全文检索**：
   - 文档标题和正文搜索
   - 支持中文分词
   - 支持标签搜索
   - 支持时间范围筛选

2. **搜索语法**：
   - 精确匹配：`"exact phrase"`
   - 或搜索：`term1 OR term2`
   - 排除搜索：`term1 -term2`
   - 字段搜索：`title:keyword`

3. **搜索建议**：
   - 实时搜索建议（输入时显示）
   - 热门搜索词
   - 最近搜索记录

#### 10.2.2 搜索结果

1. **高亮显示**：
   - 搜索词在结果中高亮
   - 显示匹配上下文摘要

2. **结果排序**：
   - 相关度排序（默认）
   - 时间排序
   - 标题排序

3. **分页**：
   - 默认每页 20 条
   - 支持游标分页

#### 10.2.3 性能目标

| 指标 | 目标 |
|------|------|
| 搜索响应时间 | < 200ms（95th percentile） |
| 索引更新延迟 | < 5s |
| 最大文档数 | 支持 100,000 文档 |

### 10.3 技术实现建议

| 方案 | 适用场景 | 说明 |
|------|----------|------|
| MySQL FULLTEXT | 小规模（< 10k 文档） | 简单，无额外依赖 |
| Elasticsearch | 中大规模 | 功能强大，需额外服务 |
| Meilisearch | 中规模 | 轻量，开箱即用 |
| SQLite FTS5 | 本地/小型 | 内置全文搜索 |

**推荐**：MySQL FULLTEXT 作为基础，逐步迁移到 Meilisearch（如果需要）。

### 10.4 优先级

**P1**

### 10.5 验收标准

- [ ] 中文分词准确
- [ ] 搜索结果高亮显示
- [ ] 支持搜索语法（精确匹配、或、排除）
- [ ] 支持标签和时间筛选
- [ ] 搜索建议实时显示
- [ ] 结果分页正常工作

## 十一、大文档性能优化需求

### 11.1 用户故事

> **作为**需要编辑长篇文档的用户，**我想要**编辑大文档时保持流畅，**以便**不打断创作思路。

### 11.2 功能描述

#### 11.2.1 编辑器性能

1. **虚拟滚动**：
   - 只渲染可视区域内容
   - 支持 100,000+ 字符文档流畅编辑

2. **增量保存**：
   - 检测文档变化增量保存
   - 不保存未变化部分

3. **防抖优化**：
   - 自动保存防抖：2s → 根据文档大小自适应
   - 搜索防抖：300ms → 150ms

#### 11.2.2 加载性能

1. **文档懒加载**：
   - 大文档分块加载
   - 显示加载进度

2. **预加载策略**：
   - 当前段落 + 前后各 1 段落预加载
   - 编辑器初始化时预加载前 50 行

3. **图片优化**：
   - 大图片压缩上传
   - 图片懒加载
   - 图片占位符

#### 11.2.3 内存管理

1. **内存监控**：
   - 监控页面内存使用
   - 大文档超过阈值时给出警告

2. **垃圾回收**：
   - 编辑器历史记录限制（默认 100 步）
   - 定时清理无用对象

### 11.3 性能指标目标

| 指标 | 目标 | 测试场景 |
|------|------|----------|
| 100KB 文档首次加载 | < 2s | 3G 网络 |
| 500KB 文档编辑响应 | < 100ms | 持续输入 |
| 内存占用（1MB 文档） | < 200MB | 编辑 30 分钟 |
| 自动保存成功率 | > 99.9% | 持续使用 1 小时 |

### 11.4 优先级

### 11.5 验收标准

- [ ] 100KB 文档加载 < 2s
- [ ] 500KB 文档编辑无明显卡顿
- [ ] 自动保存防抖自适应
- [ ] 内存占用在合理范围
- [ ] 大图片自动压缩
- [ ] 图片懒加载正常
- [ ] Playwright 性能测试通过

## 十二、编辑器升级需求

### 12.1 用户故事

> **作为**需要丰富文档样式的用户，**我想要**文本颜色选择和高亮背景色批注功能，**以便**制作更专业的文档。

### 12.2 功能描述

#### 12.2.1 TipTap 编辑器升级

**当前版本**：TipTap 3.7.2
**目标**：升级到最新稳定版本（TipTap 3.x 最新）

1. **升级范围**：
   - 升级 `@tiptap/core` 及所有扩展
   - 迁移 breaking changes
   - 验证所有现有功能

2. **已知已有扩展**（确认保留）：
   - `@tiptap/extension-color`（已安装）
   - `@tiptap/extension-highlight`（已安装）

#### 12.2.2 文本颜色选择

1. **功能**：
   - 选中文字后可通过工具栏设置文字颜色
   - 颜色选择器支持预设色板 + 自定义 HEX 输入

2. **预设颜色**：
   ```
   #000000 (黑)  #666666 (灰)  #ffffff (白)
   #ff0000 (红)  #ff6600 (橙)  #ffcc00 (黄)
   #00cc00 (绿)  #0099ff (蓝)  #9933ff (紫)
   ```

3. **交互**：
   - 工具栏添加颜色图标按钮
   - 点击弹出颜色选择面板
   - 选中后实时预览

#### 12.2.3 高亮背景色批注

1. **功能**：
   - 选中文字后设置高亮背景色
   - 高亮颜色与文字颜色独立
   - 支持 6 种高亮颜色

2. **高亮颜色**：
   ```
   #ffeb3b (黄色)  #a5d6a7 (绿色)  #90caf9 (蓝色)
   #ce93d8 (紫色)  #ffab91 (橙色)  #ef9a9a (红色)
   ```

3. **交互**：
   - 工具栏添加高亮图标按钮
   - 点击弹出高亮颜色选择
   - 已有高亮的文字再次点击可清除

### 12.3 交互设计要点

| 场景 | 行为 |
|------|------|
| 点击颜色按钮 | 弹出颜色选择面板，150ms fade-in |
| 选择颜色 | 立即应用到选中文本 |
| 取消选择 | 点击外部或按 Esc 关闭面板 |
| 颜色面板定位 | 优先显示在按钮下方，空间不足时显示在上方 |
